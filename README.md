## Overview

Pico is a ChatGPT-style assistant with three parts:

- **Chat:** multi-model conversations with streaming, markdown, math, and attachments.
- **Agents and tools:** task-focused assistants (study, career, business, creative, and more) with browser-side utilities such as PDF, QR, image, and formatting tools.
- **Artifacts:** React apps and pages generated by the assistant are bundled in the browser with `esbuild-wasm` and shown in a sandboxed preview. No build server is needed.

## Features

| Area | Capabilities |
|---|---|
| **Chat** | Streaming replies, stop generation, markdown and syntax highlighting, KaTeX math, chat folders and search, per-chat model and parameter settings, export and import, multi-language UI |
| **Agents** | Ten agents, each with a persona and a set of tools. Core chat runs when no agent is selected. Chat history is kept per agent |
| **Tools** | PDF merge, split, and export to JPG; images to PDF; image conversion and resizing; QR and barcode generation and scanning; JSON, XML, and SQL formatting; regex tester; text diff; unit and currency conversion; Pomodoro, reminders, and scratchpad; stock photo search |
| **Artifacts** | Automatic detection from fenced code, live streaming preview, file tree and code viewer, ZIP export, sandboxed iframe preview with an in-memory storage shim |
| **Attachments** | Text extraction from PDF and DOCX files (server-side, up to 10 MB) |
| **Image generation** | Image studio backed by Gemini image models, with an optional NanoBanana provider |
| **Sync** | Optional Google Drive sync of local data |

## Architecture

```text
┌──────────────────────┐   /api/chat, /api/agent/*    ┌────────────────────┐   ┌─────────────────────┐
│ apps/web/                 │ ───────────────────────────▶ │ services/api/           │──▶│ Gemini / OpenRouter │
│ React, Vite, Zustand │ ◀─────────── SSE / JSON ──── │ Express, SQLite    │◀──│ (LLM and image APIs)│
└──────────────────────┘                              └────────────────────┘   └─────────────────────┘
        │
        │  artifact code blocks
        ▼
┌──────────────────────────────────────────────┐
│ esbuild-wasm bundler → virtual files → HTML  │
│ sandboxed iframe (sandbox="allow-scripts")   │
└──────────────────────────────────────────────┘
```

- The browser never receives provider API keys. All keys live in `services/api/.env`.
- The backend stores agent conversation history in SQLite (`node:sqlite`).
- Tools that need a third-party API are called through the backend, so keys stay server-side.

## Getting Started

### Prerequisites

- **Node.js 22.5 or later** for the backend (it uses the built-in `node:sqlite` module).
- **Node.js 18 or later** for the web app.
- **Yarn 1** for the web app (`npm install -g yarn`).
- A **Gemini API key** (`GEMINI_API_KEY`), or an **OpenRouter key** if you set `LLM_PROVIDER=openrouter`.

### 1. Backend

```bash
cd services/api
cp .env.example .env        # then add your keys
npm install
npm run dev                 # starts on http://localhost:3001
```

### 2. Web app

```bash
cd apps/web
cp .env.example .env        # set the backend endpoint and optional keys
yarn install
yarn dev                    # starts on http://localhost:5173
```

### Production build

```bash
cd apps/web
yarn build
yarn preview
```

### Docker

The web app includes a Dockerfile and compose file:

```bash
cd apps/web
docker compose up --build
```

## Configuration

### Backend (`services/api/.env`)

| Variable | Required | Description |
|---|---|---|
| `GEMINI_API_KEY` | Yes | Gemini key for chat and image generation |
| `LLM_PROVIDER` | No | `gemini` (default) or `openrouter` |
| `OPENROUTER_API_KEY` | If OpenRouter | OpenRouter key |
| `GEMINI_MODEL` | No | Chat model override |
| `GEMINI_IMAGE_MODEL` | No | Image model override |
| `GEMINI_BASE_URL` | No | Custom Gemini-compatible base URL |
| `NANOBANANA_API_KEY` | No | Optional second image provider |
| `NANOBANANA_CALLBACK_URL` | No | Public webhook URL for NanoBanana |
| `PEXELS_API_KEY` | For stock search | Pexels key |
| `PIXABAY_API_KEY` | No | Second stock-photo provider |
| `VISUALCROSSING_API_KEY` | No | Weather provider (keyless fallback when unset) |
| `FREECRYPTOAPI_KEY` | No | Crypto prices (CoinGecko fallback when unset) |
| `EXCHANGERATE_API_KEY` | No | Currency rates (open.er-api.com fallback when unset) |
| `PORT` | No | Server port (default `3001`) |
| `CORS_ORIGIN` | No | Allowed origin for the web app, for example `http://localhost:5173` |

### Web (`apps/web/.env`)

| Variable | Description |
|---|---|
| `VITE_CUSTOM_API_ENDPOINT` | Backend endpoint used by the app |
| `VITE_DEFAULT_API_ENDPOINT` | Default endpoint if no custom one is set |
| `VITE_OPENAI_API_KEY` | Optional client-side key (not recommended for production) |
| `VITE_DEFAULT_SYSTEM_MESSAGE` | Optional default system message |
| `VITE_GOOGLE_CLIENT_ID` | Google OAuth client ID for Drive sync |

Never commit `.env` files. Both `services/api/.gitignore` and `apps/web/.gitignore` exclude them.

## Security

- **Server-side keys.** Provider keys are read only by the backend.
- **Sandboxed previews.** Generated artifacts run in an iframe with `sandbox="allow-scripts"`. Same-origin access, top navigation, and popups are not allowed.
- **Controlled navigation.** Links and form submissions inside a preview are routed through a `postMessage` bridge.
- **Input limits.** Attachments are capped at 10 MB. Request body sizes are limited per route.

To report a vulnerability, open a private security advisory on GitHub rather than a public issue.
